ESP documentation

This service checks the ASP request, authenticates the signer, calls eKYC and the CA, and returns EsignResp. The console at / lists every operation and audit event held in this process.

Onboarding an application provider

The console page Applications registers an ASP. A signed Esign request is accepted only when that aspId is onboarded and the certificate inside the XML signature is the registered one. An unknown ASP is error 106. A different certificate is error 104. Status requests use 301 for both.

The reference ASP publishes its signing certificate at http://localhost:8081/api/v1/meta/certificate. Paste that PEM, or ask this ESP to fetch it:

{
  "aspId": "ASP001",
  "name": "Reference application",
  "certificateUrl": "http://localhost:8081/api/v1/meta/certificate"
}

Esign request

The body is application/xml. It must carry an enveloped XML signature. Verification uses the certificate inside that signature. A missing signature is error 107. A signature that does not validate is 104. Both still use HTTP 200.

<Esign ver="3.3" signerid="demo.user@username.ESP001" ts="2026-10-13T14:13:34+05:30"
  txn="ASP202610131413348d95b" maxWaitPeriod="60" aspId="ASP001"
  responseUrl="http://localhost:8081/api/v1/esign/callback"
  redirectUrl="http://localhost:8081/api/v1/esign/return" signingAlgorithm="RSA">
  <Docs>
    <InputHash id="1" hashAlgorithm="SHA256" docInfo="Sample agreement"
      docUrl="http://localhost:8081/api/v1/documents/DOCUMENT_ID/prepared"
      responseSigType="PKCS7pdf">b1333fa4a04f9597efc940d478a183573d0c8196b2c33e37fdce7872a831aa54</InputHash>
  </Docs>
</Esign>
CheckRule
ver3.3, or error 103
tsISO-8601 offset within 30 minutes, or error 110
txn1–50 characters from A-Za-z0-9._:-, unique per ASP for the IST day after acceptance (112)
aspIdMust be onboarded, and the signing certificate must match that registration (106 or 104)
signeridid@username|Mobile|PAN.ESP001 (102)
maxWaitPeriod1–10080 minutes (111). Spec default is 1440
Documents1 to 5. Hash is 64 hex characters, algorithm SHA256, docUrl is http or https, docInfo is 1–50 characters

The usual client is the ASP. Posting the XML above without a signature shows the HTTP 200 error form:

curl.exe -s -H "Content-Type: application/xml" -d "<Esign ver="3.3"/>" http://localhost:8082/api/v1/esign

Acknowledgement

A valid request is stored and answered before the signer authenticates. resCode is required later inside txnref.

<EsignResp ver="3.3" status="2" ts="2026-10-13T14:13:34+05:30"
  txn="ASP202610131413348d95b" resCode="ESP567ba0b6dd44"/>

After PIN and OTP succeed, the ESP signs this response, posts it to responseUrl, and form-posts txnref to redirectUrl.

<EsignResp ver="3.3" status="1" ts="2026-10-13T14:20:10+05:30"
  txn="ASP202610131413348d95b" resCode="ESP567ba0b6dd44">
  <UserX509Certificate>base64 DER of the short-lived signer certificate</UserX509Certificate>
  <Signatures>
    <DocSignature id="1" sigHashAlgorithm="SHA256" error="">base64 CMS or raw signature</DocSignature>
  </Signatures>
</EsignResp>

Unchecking a document on the signer page cancels only that document. Its DocSignature carries error 206.

Signer authentication

Ask for a one-time password after you have a txnref from an accepted request. Demo mode returns the digits because no SMS gateway is connected. The value sent onward to eKYC is the SHA-256 hex of those digits, not the digits themselves. The PIN on the wire is SHA-256(txn + SHA-256(pin)).

curl.exe -s -H "Content-Type: application/json" -d "{\"txnref\":\"BASE64_TXN_PIPE_RESCODE\",\"signerId\":\"demo.user@username.ESP001\"}" http://localhost:8082/api/v1/esign/auth/otp
{"sent":true,"demoOtp":"048213"}

Only SMSOTP is enabled. The signer page posts the form to /api/v1/esign/auth. Consent text, when eKYC requires it, is exactly I hereby authorize this KYC Information authentication.

Five failed attempts lock that signer for that transaction. A scheduler every 30 seconds completes a request past maxWaitPeriod with error 113. Transactions stay in memory until restart. A production ESP keeps them for at least 30 days.

Read one operation, including its authentication URL:

GET /api/v1/esign/transactions/ASP202610131413348d95b

Status

The ASP sends this signed XML when it polls. A bad timestamp, ASP id, or signature on a status request is reported as 301. An unknown transaction is 302.

<EsignStatus ver="3.3" ts="2026-10-13T14:25:00+05:30"
  txn="ASP202610131413348d95b" aspId="ASP001"/>

The response is an EsignResp. Status 2 is still waiting, 1 includes signatures, and 0 carries error.

Errors

XML APIs return HTTP 200. The code is the error attribute. JSON APIs, such as a bad OTP request, use the catalogue HTTP status:

{"errorCode":"114","errorMessage":"Authentication failed. User credentials invalid."}

Audit actions include ESIGN_ACCEPTED, ESIGN_REJECTED, OTP_REQUESTED, ESIGN_COMPLETED, ESIGN_FAILED, CALLBACK, CALLBACK_FAILED, STATUS_READ, and STATUS_REJECTED. The same list is on Logs. Every code is at /api/v1/meta/error-codes.

Other services

  • ASP builds the PDF and sends the signed Esign request.
  • eKYC checks the PIN and OTP. The ASP never receives the KYC attributes.
  • CA issues the certificate and signs each document hash.
