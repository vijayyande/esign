ASP documentation

This service is the application. It stores a file, builds the PDF that will be signed, asks the ESP to sign the PDF byte-range hash, and writes the returned CMS signature back into that PDF.

Signing flow

  1. Upload a file with docInfo (1–50 characters).
  2. For a CMS signature, place the visual box on the page preview. Coordinates are PDF points from the top-left.
  3. POST /api/v1/esign/requests. The ASP signs an Esign document (version 3.3) and posts it to the ESP.
  4. Open authenticationUrl. The signer enters PIN 123456 and the one-time password shown on that page.
  5. The ESP posts EsignResp here, then the browser returns. Download signed.pdf.

Demo signer: demo.user@username.ESP001. Aliases: 9876543210@Mobile.ESP001 and ABCDE1234F@PAN.ESP001.

Upload

An existing PDF is signed in place. Any other file is wrapped on an A4 page, and the original bytes are attached. The upload limit is 20 MB.

curl.exe -s -F "file=@agreement.txt" -F "docInfo=Sample agreement" http://localhost:8081/api/v1/documents
{
  "documentId": "ac9fe9e8c23044dab791594268813cec",
  "fileName": "agreement.txt",
  "docInfo": "Sample agreement",
  "hashHex": "b1333fa4a04f9597efc940d478a183573d0c8196b2c33e37fdce7872a831aa54",
  "docUrl": "/api/v1/documents/ac9fe9e8c23044dab791594268813cec/content"
}

docInfo longer than 50 characters is rejected:

{"errorCode":"204","errorMessage":"Invalid document information"}

Start signing

responseSigType defaults to PKCS7pdf. signingAlgorithm is RSA or ECDSA. maxWaitPeriod is minutes from 1 to 10080. Up to five document ids can be sent.

curl.exe -s -H "Content-Type: application/json" -d "{\"documentIds\":[\"DOCUMENT_ID\"],\"signerId\":\"demo.user@username.ESP001\",\"signingAlgorithm\":\"RSA\",\"responseSigType\":\"PKCS7pdf\",\"maxWaitPeriod\":60,\"signaturePage\":1,\"signatureX\":36,\"signatureY\":742,\"signatureWidth\":190,\"signatureHeight\":64}" http://localhost:8081/api/v1/esign/requests
{
  "txn": "ASP202610131413348d95b",
  "resCode": "ESP567ba0b6dd44",
  "status": "2",
  "authenticationUrl": "http://localhost:8082/api/v1/esign/auth?txnref=..."
}

status 2 means the ESP accepted the request and is waiting for the signer. 1 is completed. 0 is failed. If the callback is missed, poll with POST /api/v1/esign/transactions/{txn}/status.

The ASP builds this signed XML and posts it to the ESP. The Signature element is an enveloped XML-DSig. The hash is the SHA-256 of the PDF byte range, not the original file, whenever the signature type is PKCS7, PKCS7pdf, or PKCS7complete.

<Esign ver="3.3" signerid="demo.user@username.ESP001" ts="2026-10-13T14:13:34+05:30"
  txn="ASP202610131413348d95b" maxWaitPeriod="60" aspId="ASP001"
  responseUrl="http://localhost:8081/api/v1/esign/callback"
  redirectUrl="http://localhost:8081/api/v1/esign/return" signingAlgorithm="RSA">
  <Docs>
    <InputHash id="1" hashAlgorithm="SHA256" docInfo="Sample agreement"
      docUrl="http://localhost:8081/api/v1/documents/DOCUMENT_ID/prepared"
      responseSigType="PKCS7pdf">64-hex-sha256</InputHash>
  </Docs>
</Esign>

raw hashes the original file and does not embed a visual PDF signature. docUrl is then /content.

Signature location

Omit the five signature* fields to use the default: a 190 by 64 point box, 36 points from the left and the bottom of the last page. When they are set, signatureX and signatureY are the top-left of the box on the rendered page. The server converts that into PDF user space, including pages rotated 90, 180, or 270 degrees.

Page geometry before you choose a place:

GET /api/v1/documents/DOCUMENT_ID/pages

[{"page":1,"width":595.0,"height":842.0,"rotation":0}]

PDF files

After the ESP callback, GET /api/v1/documents/{id}/signature reports whether the CMS matches the byte-range hash:

{
  "documentId": "DOCUMENT_ID",
  "hashHex": "64 hex characters of the PDF byte range",
  "responseSigType": "PKCS7pdf",
  "signatureBase64": "CMS",
  "verified": true,
  "error": "",
  "pdfError": "",
  "signedPdf": "/api/v1/documents/DOCUMENT_ID/signed.pdf"
}

PKCS7pdf and PKCS7complete include the CA certificate in the CMS. PKCS7 contains only the signer certificate. There is no OCSP or CRL in this reference.

Errors

JSON calls use the HTTP status from the catalogue. XML calls, including the ESP callback, return HTTP 200 and put the failure in the body. The full list is /api/v1/meta/error-codes. Codes this service surfaces directly:

CodeWhen
108The sign request has no document id
109More than five documents
204docInfo is missing or longer than 50 characters
202responseSigType is not raw, PKCS7, PKCS7pdf, or PKCS7complete
302Status poll for an unknown transaction

Uploads stay on disk under data/asp. A restart forgets the in-memory document index, so old ids stop resolving until you upload again.

Other services

  • ESP authenticates the signer and returns EsignResp.
  • eKYC checks the PIN and SMS OTP. KYC attributes stay there.
  • CA issues the short-lived certificate and signs the hash.
