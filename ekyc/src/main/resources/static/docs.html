eKYC documentation

This service authenticates a signer and holds the KYC attributes. A successful eKycResp is returned only to the ESP. The ASP does not receive it.

One-time password

curl.exe -s -H "Content-Type: application/json" -d "{\"signerId\":\"demo.user@username.ESP001\",\"txn\":\"KYC001\"}" http://localhost:8083/api/v1/otp
{"sent":true,"demoOtp":"048213"}

The ESP does not send those digits to this service. The second-factor value is lowercase hex SHA-256 of the six digits. Turn esign.expose-demo-otp off before any shared deployment. esign.seed-demo-user creates the demo signer on startup.

An unknown signer id shape is 102. A well-formed id that is not enrolled is 114.

eKYC request

The ESP signs this XML. pinhash is lowercase hex SHA-256(txn + SHA-256(pin)). For PIN 123456, the inner hash is 8d969eef6ecad3c29a3a629280e686cf0c3f5d5a86aff3ca12020c923adc6c92. SecondFactor is the Base64 of a SecondFactorRequest. Omit it and the response status is 2, meaning the PIN was accepted and the second factor is still required.

<eKycReq ver="3.3" signerid="demo.user@username.ESP001" ts="2026-10-13T14:20:00+05:30"
  txn="KYC001" pinhash="64-hex-sha256-of-txn-plus-pin-hash">
  <SecondFactor>base64 of the SecondFactorRequest below</SecondFactor>
</eKycReq>
<SecondFactorRequest ver="1.0" signerid="demo.user@username.ESP001" ts="2026-10-13T14:20:00+05:30"
  txn="KYC001" authenticationType="SMSOTP"
  consent="I hereby authorize this KYC Information authentication.">
  <SMSOTP>lowercase hex SHA-256 of the six-digit OTP</SMSOTP>
</SecondFactorRequest>

The consent sentence must match exactly. authenticationType must be SMSOTP. TOTP, mobile access tokens, FIDO, and public-key authentication are rejected. Five failed attempts lock that signer for that transaction. A completed transaction is not replayed.

A success response is signed and includes the KYC attributes. Status 1 is success, 0 is failure, and 2 is waiting for the second factor. XML still returns HTTP 200.

<eKycResp ver="3.3" status="1" signerid="demo.user@username.ESP001" ts="2026-10-13T14:20:01+05:30"
  txn="KYC001" respCode="KYC...">
  <kycData name="Demo Signer" mobile="9876543210" email="demo@example.com" address="1 MG Road"
    stateProvince="KA" country="IN" postalCode="560001" PAN="ABCDE1234F" DOB="1990-01-15"
    Gender="M" Aadhaar="1234" eKYCtype="OFFLINE_AADHAAR"/>
  <Photo>base64 PNG</Photo>
</eKycResp>

Signer id forms are name@username.ESP001, a 10-digit mobile@Mobile.ESP001, or PAN@PAN.ESP001. The demo account also matches 9876543210@Mobile.ESP001 and ABCDE1234F@PAN.ESP001.

Subscriber

curl.exe -s -H "Content-Type: application/json" -d "{\"signerId\":\"demo.user@username.ESP001\",\"pin\":\"123456\"}" http://localhost:8083/api/v1/subscriber/login
{"token":"uuid","signerId":"demo.user@username.ESP001"}
curl.exe -s -H "Authorization: Bearer TOKEN" http://localhost:8083/api/v1/subscriber/profile

Profile update accepts any of email, address, stateProvince, and postalCode. A new PIN must be at least 6 characters. A missing or expired bearer token is 114.

Enrolment is POST /api/v1/accounts. The demo id already exists, so this example uses a new id. Personal accounts cannot share a mobile or PAN. ekycType is OFFLINE_AADHAAR, BANK, ORGANISATIONAL, or FOREIGN_NATIONAL. A foreign national must not use country IN. Bank enrolment requires a stored Bank KYC transaction. Organisation enrolment requires the organisation id, name, signatory name, and certificate id.

Bank KYC

Version is 1.0. The body must be signed. A malformed body is 401 rather than a signature error, because the signature is checked after the XML parses. IFSC is optional. When present it must be 11 letters or digits, otherwise 406. Gender is mandatory. An account number that is not 6–18 digits is 401. A missing photo is 420. Photo format is BMP, JPG, or PNG.

<BankKYC ver="1.0" ts="2026-10-13T14:20:00+05:30" txn="BANK20261013001"
  bankName="Demo Bank" accountNumber="123456789012">
  <KYCInfo name="New Signer" mobile="9123456780" email="new@example.com" address="1 MG Road"
    stateProvince="KA" country="IN" postalCode="560001" dateOfBirth="1992-04-02" gender="F"
    pan="PQRST1234Z" Aadhaar="5678"/>
  <Photo format="PNG">iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg==</Photo>
</BankKYC>
<BankKYCResp ver="1.0" ts="2026-10-13T14:20:01+05:30" txn="BANK20261013001" status="1" resCode="BANK..."/>

A failure uses the same element with status="0", error, errorCode, and errorMessage.

Organisation KYC

API 3.3 removed the old organisational option-1 request and kept error codes 501–521. OrgKYC is the payload this project validates against that list. physicalVerification must contain the person's name. Either PAN or the last four digits of Aadhaar is required.

<OrgKYC ver="1.0" ts="2026-10-13T14:20:00+05:30" txn="ORG20261013001"
  kycOrgId="ORG001" orgName="Demo Org" orgUnit="Finance" orgSigName="Authorised Signatory"
  orgSigCertId="CERT001" employeeId="E100" physicalVerification="New Signer">
  <KYCInfo name="New Signer" mobile="9123456780" address="1 MG Road" stateProvince="KA"
    country="IN" postalCode="560001" dateOfBirth="1992-04-02" gender="F" pan="PQRST1234Z"/>

</OrgKYC>

Errors

JSON uses the HTTP status from the catalogue. XML returns HTTP 200 with the code in the body. The full list is /api/v1/meta/error-codes.

RangeUsed for
101–114eKYC authentication: format, signer id, version, signature, timestamp, and PIN or OTP failure (114)
401–420, 499Bank KYC
501–521, 599Organisation KYC. A bad PAN, or missing both PAN and Aadhaar, is 517
